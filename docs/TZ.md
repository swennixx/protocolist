# Техническое задание: «Протоколист»

Локальный сервис расшифровки совещаний: запись встречи превращается в текст по спикерам, краткое содержание, список решений и задач, а весь архив встреч доступен для смыслового поиска и вопросов в формате чата.

## 1. Цель и ценность

**Проблема.** После созвонов теряются договорённости: протокол никто не пишет, запись никто не пересматривает. Облачные сервисы (Otter, Fireflies, tl;dv) плохо работают с русским языком и отправляют записи на чужие серверы — для юристов, медицины, HR и госзаказчиков это неприемлемо.

**Решение.** Сервис, который работает целиком на своём сервере или ноутбуке: ни одна запись и ни одна строка текста не покидают контур заказчика.

**Цель проекта для портфолио.** Показать полный цикл прикладного ML: выбор и сравнение моделей с честными метриками, пайплайн обработки, продакшен-API, фоновые задачи и продуманный интерфейс.

## 2. Пользователи и сценарии

| Роль | Сценарий |
|---|---|
| Руководитель | Загрузил запись планёрки, через 3 минуты получил список задач с ответственными и сроками, отправил его в чат команды |
| Сотрудник, пропустивший встречу | Прочитал выжимку, по клику на решение прослушал нужный фрагмент записи |
| Любой участник | Спросил «что решили по бюджету на Q4?» и получил ответ со ссылками на фрагменты трёх разных встреч |
| Юрист / HR | Получил дословную стенограмму с таймкодами и экспортировал её в DOCX |

## 3. Функциональные требования

### 3.1. Загрузка записи
- Форматы: MP3, M4A, WAV, OGG, OPUS, WEBM, MP4, MOV (из видео извлекается звук через ffmpeg).
- Загрузка перетаскиванием или через выбор файла; размер до 2 ГБ, длительность до 4 часов.
- При загрузке пользователь указывает название (по умолчанию — имя файла), язык (авто / русский / английский) и, при желании, ожидаемое число спикеров.
- Загрузка идёт частями (chunked upload) с возможностью продолжить после обрыва.

### 3.2. Обработка
Пайплайн из этапов, каждый этап виден в интерфейсе с прогрессом в реальном времени (SSE):

1. **Подготовка** — конвертация в WAV 16 кГц моно, нормализация громкости, опционально шумоподавление.
2. **Распознавание речи** — Whisper large-v3 (на Apple Silicon через `mlx-whisper`, на NVIDIA через `faster-whisper`), пословные таймкоды, VAD для пропуска тишины.
3. **Диаризация** — pyannote/speaker-diarization-community-1, если есть доступ к модели; иначе собственный алгоритм: фразы по паузам → эмбеддинги голоса WeSpeaker → кластеризация. Затем выравнивание слов по спикерам.
4. **Постобработка** — расстановка пунктуации и регистра, склейка реплик одного спикера, удаление слов-паразитов в режиме «чистый текст» (дословный текст сохраняется).
5. **Анализ** — локальная LLM (Qwen 3 8B через Ollama) строит выжимку, решения, задачи (что / кто / срок) и темы с таймкодами.
6. **Индексация** — для каждой реплики считается эмбеддинг (multilingual-e5-small), реплики кладутся в векторный индекс.

Требования к обработке:
- Задачи выполняются в фоне (очередь), интерфейс не блокируется, можно загрузить несколько файлов подряд.
- При сбое этапа запись не теряется: этап можно перезапустить, пройденные этапы не повторяются.
- Встречу можно открыть до завершения анализа — транскрипт появляется сразу после этапа 3.

### 3.3. Просмотр встречи
- Плеер с волновой формой, раскрашенной по спикерам; скорость воспроизведения 0,75–2×; перемотка ±10 с.
- Транскрипт: реплики со спикером, таймкодом и текстом. Текущая реплика подсвечивается и автоматически прокручивается; клик по реплике перематывает запись.
- Переключатель «дословно / чистый текст».
- Переименование спикеров («Спикер 2» → «Анна, PM»), изменение применяется ко всей встрече.
- Ручное исправление текста реплики (с сохранением исходного варианта).
- Вкладки боковой панели: **Выжимка**, **Решения**, **Задачи**, **Спикеры** (доля времени, число реплик).
- Каждое решение и каждая задача ссылаются на фрагмент записи — клик перематывает к нему.
- Поиск по тексту внутри встречи с подсветкой совпадений.

### 3.4. Архив и поиск
- Список встреч: название, дата, длительность, участники, статус обработки; сортировка и фильтр по дате и участнику.
- Поиск по всему архиву в двух режимах: точный (полнотекстовый) и смысловой (векторный, находит перефразировки).
- Результат поиска — фрагмент с контекстом, названием встречи и таймкодом; клик открывает встречу на нужном месте.

### 3.5. Вопросы к архиву (чат)
- Пользователь задаёт вопрос на естественном языке.
- Ответ строится по схеме RAG: гибридный поиск (векторы + полнотекстовый поиск Postgres) → найденные реплики с соседними для контекста → генерация LLM.
- Каждое утверждение в ответе сопровождается ссылкой-цитатой на фрагмент встречи; если ответа в архиве нет, система так и говорит, а не выдумывает.
- Можно ограничить вопрос одной встречей или диапазоном дат.

### 3.6. Экспорт
- DOCX (протокол: выжимка, решения, задачи, стенограмма), Markdown, SRT/VTT (субтитры), JSON (полные данные).
- Копирование списка задач одним кликом в формате для мессенджера.

### 3.7. Настройки
- Выбор модели распознавания (tiny / small / medium / large-v3 / large-v3-turbo) с подсказкой о скорости и качестве.
- Выбор LLM для анализа, шаблон выжимки (краткий / подробный / протокол).
- Словарь терминов (названия компании, продуктов, фамилии) — передаётся в Whisper как initial prompt и повышает точность.

## 4. Нефункциональные требования

| Параметр | Требование |
|---|---|
| Приватность | Никаких внешних сетевых запросов при обработке; модели скачиваются один раз при установке |
| Скорость | Запись 60 минут на Apple M4 / RTX 3060: не дольше 6 минут до готового транскрипта |
| Качество ASR | WER на русском не выше 12% на тестовом наборе (см. раздел 6) |
| Качество диаризации | DER не выше 20% на тестовом наборе |
| Надёжность | Перезапуск сервиса не теряет задачи в очереди |
| Развёртывание | Одна команда `docker compose up`; отдельный профиль для GPU |
| Интерфейс | Адаптивная вёрстка от 360 px, светлая и тёмная темы, управление с клавиатуры (пробел — пауза, ←/→ — перемотка) |

## 5. Архитектура

```
React SPA ──HTTP/SSE──▶ FastAPI ──▶ Postgres (встречи, реплики, задачи, pgvector)
                           │
                           └──▶ Worker (очередь — та же Postgres)
                                            ├─ ffmpeg
                                            ├─ Whisper (mlx / faster-whisper)
                                            ├─ pyannote / WeSpeaker + кластеризация
                                            ├─ e5 embeddings
                                            └─ Ollama (Qwen 3 8B)
```

- **Backend:** Python 3.13, FastAPI, SQLAlchemy 2 + Alembic; очередь задач — таблица в Postgres (`FOR UPDATE SKIP LOCKED`).
- **Хранилище:** Postgres 16 + pgvector (векторы и полнотекстовый поиск в одной базе), аудиофайлы на диске или в S3-совместимом хранилище.
- **Frontend:** React 19, TypeScript, Vite; без UI-китов, собственная дизайн-система на CSS-переменных.
- **Инфраструктура:** Docker Compose, GitHub Actions (линтеры, тесты, сборка образов).

### Основные сущности
- `Meeting` — название, дата, длительность, язык, статус, путь к аудио.
- `Speaker` — метка диаризации, отображаемое имя, цвет.
- `Segment` — спикер, начало, конец, текст дословный, текст чистый, слова с таймкодами.
- `Summary`, `Decision`, `Task` (текст, ответственный, срок, ссылка на сегмент).
- `Chunk` — фрагмент для поиска, эмбеддинг.
- `Job` — этап, статус, прогресс, ошибка.

### API (основное)
| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/meetings` | Создать встречу и начать загрузку |
| GET | `/api/meetings` | Список с фильтрами |

## 6. Оценка качества (ML-часть)

Фактические результаты — в README и `bench/results/`.

Отдельный модуль `bench/` с воспроизводимыми экспериментами; результаты публикуются в README таблицами и графиками.

- **ASR:** WER и CER на Golos (crowd + farfield) и Common Voice ru; сравнение tiny / small / medium / large-v3 / large-v3-turbo по качеству и скорости (real-time factor) на CPU, Apple Silicon и CUDA.
- **Диаризация:** DER на AMI и на собственном наборе из 10 размеченных русских записей встреч.
- **Анализ:** ручная разметка задач и решений на 20 встречах; precision / recall извлечения задач, сравнение нескольких LLM и промптов.
- **Поиск и RAG:** 100 вопросов с эталонными фрагментами; Recall@5, MRR для BM25, векторного и гибридного поиска с переранжированием и без; доля ответов без галлюцинаций (проверка по цитатам).
- Тесты качества в CI на маленьком наборе: сборка падает, если WER вырос больше чем на 1 п. п. относительно зафиксированного значения.

## 7. Интерфейс

Экраны:
1. **Встречи** — архив карточками, строка поиска, зона загрузки, статусы обработки.
2. **Обработка** — этапы пайплайна с прогрессом и оценкой оставшегося времени.
3. **Встреча** — плеер с волной, транскрипт, боковая панель с выжимкой, решениями, задачами и спикерами.
4. **Спросить** — чат по архиву с цитатами-ссылками.
5. **Настройки** — модели, шаблоны, словарь терминов.

Дизайн: светлая тема по умолчанию, спокойная палитра, один акцентный цвет, цвета спикеров из согласованной палитры, моноширинные таймкоды, плавные переходы без лишней анимации.

## 9. Решения, принятые по ходу работы

Что изменилось относительно первой версии ТЗ и почему.

| Было в ТЗ | Сделано | Почему |
|---|---|---|
| Очередь arq + Redis | Очередь в Postgres (`FOR UPDATE SKIP LOCKED`) | Одним сервисом меньше; задачи и так переживают перезапуск, потому что лежат в базе |
| pyannote 3.1 | pyannote community-1 и собственная диаризация, выбор в настройках | Модели pyannote закрыты условиями на Hugging Face. Собственный вариант (эмбеддинги WeSpeaker по фразам + кластеризация с подбором числа спикеров по силуэту) работает сразу. На синтетике своя не хуже pyannote, но на реальных совещаниях AMI pyannote как диаризатор почти вдвое точнее (DER 15,5 % против 28,8 %), а в итоговой стенограмме разница мала (23,1 % против 24,3 %). Своя в 14 раз быстрее. На русских подкастах разрыв ещё больше: pyannote DER 5,6–19,5 % против 16,9–50,5 % — своя путает людей, перехватывающих слово без паузы. По умолчанию — pyannote, своя — запасной вариант |
| Qwen 2.5 7B, один запрос | Qwen 3 8B, два запроса: обзор встречи и поиск решений/задач окнами по 40 реплик | На тестовой встрече один общий запрос к Qwen 2.5 7B дал 1 решение и 2 задачи; два узких запроса к Qwen 3 8B — 4 решения и 3 задачи с верными исполнителями. Нужна разметка на нескольких реальных встречах, чтобы мерить точно |
| Имена спикеров не предусматривались | LLM перечисляет прозвучавшие имена, код сопоставляет их со спикерами | Модель путала, кто к кому обращается. Код засчитывает только вопрос по имени с ответом следующей репликой или представление |
| Гибридный поиск с rank fusion и bge-reranker | Сходство векторов + небольшой бонус за совпадение слов | По bench/retrieval.py: полнотекстовый поиск находит нужную реплику первой в 36 % вопросов, векторы — в 79 %, а RRF ухудшал результат векторов. Reranker отложен до набора вопросов побольше |
| Нарезка реплик на фрагменты для поиска | Один вектор на реплику | Реплики и так смысловые единицы; скользящие окна добавим, если длинные монологи начнут теряться |
| — | Без `hallucination_silence_threshold` в Whisper | Опция против «галлюцинаций» в паузах выкидывала настоящие реплики: на созвоне WER 0,6 % → 5,2 % |
| Whisper на всём железе одинаково | MLX на Apple Silicon, faster-whisper на Linux | faster-whisper не использует GPU Apple, MLX — использует; на M4 turbo распознаёт 2 минуты записи за ~13 с |

## 10. Критерии приёмки
- Запись 60 минут с 4 участниками обрабатывается целиком без ручных действий.
- Метрики из раздела 4 подтверждены воспроизводимым бенчмарком.
- Все экраны работают на ширине 360 px и в тёмной теме.
- Проект разворачивается одной командой на чистой машине по инструкции из README.
